Preface — Who This Book Is For, and How to Use It

This book began as a living preparation system for one of the most technically demanding roles in modern software: Principal Performance Architect for AI/ML infrastructure. It grew through real interview cycles, production architecture reviews, and hands-on performance engineering at GPU cluster scale into a comprehensive reference that covers the full technical stack — from the physics of DRAM cell refresh to the economics of a 10,000-GPU fleet.

Every other resource covers one layer. Deep learning textbooks cover model theory without hardware. CUDA programming guides cover kernel optimization without system context. MLOps books cover pipelines without silicon understanding. Interview prep books give patterns without first-principles math. This book is the only single reference that unifies all of these into a coherent analytical system.

Target Reader

Who will get the most from this book A strong senior performance engineer — CPU, HPC, cloud, embedded, or networking background — who understands bottleneck analysis, roofline thinking, and measurement discipline, and needs the domain knowledge to apply all of that at principal level in AI/ML infrastructure.

Confidence Label System

This book uses confidence labels on all hardware specifications. Technology moves faster than publication cycles — a label tells you whether to trust a number at face value or verify it against current documentation before using it in a design decision.

LabelMeaningTrust Level
[SHIPPED]Measured on production hardware; verified against manufacturer datasheetsHigh — use in production calculations
[ANNOUNCED]Vendor-disclosed, not yet generally available or shippingMedium — verify before committing to design
[ESTIMATED]Calculated from first principles or extrapolated from known dataMedium — check the derivation, not just the value
[REPRESENTATIVE]Illustrative example; not a specific product claimConceptual — don't use in procurement decisions
[ENV-SPECIFIC]Highly cluster- and framework-dependent; will vary in your environmentDirectional — always measure in your system

Code Block Conventions

FORMULA BLOCKS (dark background) — used for: • Mathematical formulas with derivation steps • Hardware specifications with derived calculations • Pseudo-code that illustrates an algorithm at architecture level • Quick-reference tables of key production numbers Example: MFU = (FLOPs_per_step × steps_per_second) / Peak_TFLOPS = (2 × N_params × seq_len × batch_size × steps_s) / 989e12 H100 ridge point = Peak_TFLOPS / HBM_BW = 989 / 3.35 = 295 FLOP/byte
Cross-reference tags — Throughout the book you will see tags like Ch 4: Memory wall and Ch 11: KV paging. These indicate that the concept is covered in depth in the referenced chapter. Cross-references are bidirectional — each chapter links forward and backward to build a connected knowledge graph.
